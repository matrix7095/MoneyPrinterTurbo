# 已发布作品的修订与重新发布

同一内容重新发布时，创建新的业务修订，重新走研究、脚本、配音、计划、素材、成片和发布审核。旧作品、旧审核任务及媒体继续保留，不能把旧发布记录覆盖为新作品。`PUBLISHED` 记录表示曾经成功登记发布；作品当前是否公开，仍须到平台核对。

## 创建修订

管理接口为 `POST /api/v1/contents/{content_id}/published-revisions`，使用现有管理员认证。请求包含：

- `request_key`：本次修改的唯一业务请求键；响应不明时先核对已有请求，保持原键和原请求体。
- `expected_revision_id`：当前业务修订；尚未采用修订协议的历史内容为 `null`。
- `publication_id`：当前修订对应、具有真实外部作品 ID 或 URL 的发布记录 ID。
- `feedback`：本次修改目标、需保留的事实，以及已知质量或授权缺口。

相同请求会返回同一个修订，不重复创建。并发修改、过期 head、活动任务/阶段/运行，以及旧版尚未解决的发布意图都会阻止创建。接口不自动批准脚本、启动 Worker 或发布。

创建后 Content 的当前 head 转为新修订，状态进入 `PREPARING_CONTEXT/research`。继续使用普通 `prepare` 和按需运行入口。Candidate、内容根目录及旧脚本版本不重置；新脚本通过正常消费递增版本。

## 当前版本与历史边界

需要核验新收到的官方素材或许可时，可使用管理入口 `POST /api/v1/contents/{content_id}/source-media-refresh`，提交 `request_key`、非空 `expected_revision_id`、当前已接收研究的 `research_task_id` 和待独立核验的 `feedback`。该入口仅支持已经有业务修订的图文内容，且阶段仍为 `WAITING_AGENT/short_script`、脚本尚未领取执行。活动宿主、任务、阶段、有效 offer、未决发布意图或已执行的下游都会阻止补查。

通过后只取消精确关联、未执行的旧脚本待办，并新建研究任务；已完成研究、结果、旧媒体和旧预算保留。同一请求保持幂等。反馈只是待核验线索，不能替代授权凭据，入口不自动批准或发布。没有新证据时不重复启动相同研究；不能因许可缺失而把要求官方素材的视频改成全 AI 图。

新任务、素材和阶段由服务端绑定当前修订；Worker 不能指定另一修订。QC、审批和发布材料必须使用当前修订及其完整上游链。历史记录保留原输入、结果、哈希和媒体路径，不能用于跳过新审核。

新修订的可变制作文件放在独立工作命名空间，Artifact 路径仍相对于原 Content 根目录。旧来源缓存不能冒充新来源。旧任务不能重新入队或通过迟到失败上报改变新 head；旧发布结果的核对只能影响相应历史记录。

新运行获得新的 run ID 和递增 generation，拥有自己的运行轮次预算。旧任务 attempt、恢复记录、已结束运行归档和发布证据保持不变。同一 head 的活动运行重复请求复用原运行，不能刷新其预算。

## 质检与重新发布

脚本、配音、素材和完整九项成片 QC 继续使用现有门禁。官方来源不等于公开转载许可；预览、ASR 或逐帧解码通过也不等于正式成片审核通过。已知授权缺口必须如实进入审核。

重新发布使用新修订的发布任务、素材和一次性发布意图。旧版未决意图仍需先核对，不能重新点击。新修订不得把已有作品 ID 或相同作品 URL 登记为第二次发布；相同修订的相同结果重放保持幂等。每日发布预算仍按真实发布和发布意图累计。

最终核对新作品 ID、URL、平台可见性和截图，并确认旧记录未变。按现有手册在成功发布后调用正常归档服务，核对 metadata 包含完整发布记录列表、当前视频及封面；归档不会因发布结果消费而自动刷新。

## 部署与证据

迁移为历史行增加可空修订字段，并保留原列数据。部署前保存一致的私密数据库备份；部署后先按原列投影及媒体哈希核对旧数据，再启动新修订。迁移中断后重启须补齐缺失索引。

本手册描述操作协议，不代表某条新视频已经通过审核或重新发布。实际状态、当前修订和新外部作品 ID 以生产交接及真实平台证据为准。
