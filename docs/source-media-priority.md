# 产品素材优先合同

新签发的图文研究和视觉计划由服务端按内容的实际制作模式加入
`source_media_priority_version=1`。素材顺序是同型号官方宣传视频/图片优先，
AI只补已说明的信息缺口。`image_only`表示没有采用原片的图片路线，不表示全AI。

## 研究

研究结果新增可选的`source_media_search`；v1图文任务必须提供：

- `checked_pages`：实际检查的页面，结构为`{url,title,source_type}`，至少一项官方或一手来源。
- `video_search_note`：同型号官方视频、频道或媒体库的查找结果及是否能取用。
- `image_gap_reason`：原图的覆盖缺口；`source_images=[]`时不可为空。

可用的两张官方图也必须回传，不因数量少而丢弃。官方渲染图可以作为产品宣传素材，
不能仅凭画面称为实拍。盘点是来源证据，不自动证明许可或批准发布。

现有视频入口仍是候选的`video_url`：找到可用同型号官方影片后，应在选择制作模式前
补录，并走既有footage获取链路。本次没有新增图文视频混排、跨模式切换或下载器。

## 视觉计划

v1任务若有本内容已登记且在可用白名单内的`source_image`，计划必须至少实际直用一张。
将原图仅用作AI重绘参考不算直用，复用旧AI图也不能绕过原图优先。
每个`asset_request`必须填写`source_gap_reason`，指出现有素材不能表达的具体信息。
权利、对应信息是否真实、节奏是否合适仍由后续审核判断，理由字符串本身不构成批准。

v1计划消费后不再为了凑4/5张资产而自动拆段、替换原图并注入AI请求。脚本应对无法由现有
图片覆盖的关键信息写明具体语义缺口并标记`preferred_source=ai_generate`；视觉计划可在既定预算内
主动申请多张、用途各异的补图来覆盖这些缺口。数量不足或原图少本身仍不是生图依据，计划与盘点
信息一并传给视觉计划QC。

4/5张及单段8秒是节奏建议，不是必须补AI的通过条件。应先直用能支持旁白的官方产品图；不能仅为
统一风格把可用官方产品图全部替换成AI图。单一视角无法表达不同关键信息时，应按具体缺口补图，
不能只重复同一视角并更换字幕或裁切。承载不同关键信息段时，原图复用应带来实际视觉信息增量，
例如放大后展示此前看不到的真实细节；同一语义的回扣或结尾 CTA 重现产品图也可合理复用。
核心错误针对不同信息段没有新增视觉信息的重复，以及关键旁白缺少适配画面。同视角图片及不同裁切
不能被表述为多个真实场景，参数表与UI不为凑数量重绘。多个AI补图
应保持同一视觉风格；重复出现的人物或环境需保持外观与场景连续。AI补图不能伪造产品功能、参数或
UI，也不能冒充实拍或作为真实动作、测试的证据；产品外观细节以已取得的官方图片为准，无法可靠
呈现时用概念示意。

新计划签发及提交均校验当前脚本指向当前研究、研究输入哈希和当前attempt的唯一ACCEPTED
结果哈希。`source_media_search`必须精确取自这份研究，调用方不能提供另一份盘点替代。
有图片URL时，现有取图步骤通过AuditEvent记录研究结果哈希、实际取得的原图与未取得URL；
计划原图白名单只接受同一收据的本内容source_image。旧索引或另一次研究的图片不能冒充。
`source_media_acquisition`将研究发现、实际下载成功和未取得的URL分别传给计划与QC。
全下载失败不等于官网没有图，单张失败也不意味着所有镜头都可以改成AI。

仍在脚本审核、准备或失败状态的旧图文内容若尚未盘点，正常准备/脚本审批入口会签发新的
CONTENT_RESEARCH，复用既有去重与租约机制。新研究消费后签发新脚本并重新走QC；不会把
旧脚本/QC或配音错误绑定到新研究。PUBLISHED内容不会被这条补盘点路径自动返工。

## 历史边界

旧任务没有版本标记时保留旧合同，已有任务去重返回时不回填新输入。
新增可选字段省略时不进入规范化结果，避免改变旧接受结果哈希及幂等重提。
footage合同与历史自动补图行为保持原样；旧成片、研究、任务、attempt和发布记录不改写。
旧任务继续按冻结合同读回；以旧未盘点研究签发新v1计划会被拒绝，须完成真实补盘点。
