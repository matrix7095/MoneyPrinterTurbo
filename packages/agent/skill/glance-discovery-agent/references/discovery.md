# 来源发现补充规则

仅用于 `source_discovery`：

1. 读取来源、范围、最大候选数与历史方向；优先近期的官方或可识别原创来源。
2. 解析跳转并记录最终规范 URL；平台 ID 可用时作为 `external_id`。
3. 手动模式只记录页面事实与视频入口，是否适合内部使用由人工判断。
   Handsfree 以服务端现行指令与 Schema 为准：主动核验真实权威公开许可及拟用素材的适用范围，
   如实填写已有 `rights_status` / `rights_note`。仅确有适用依据时填 `EXPLICIT_LICENSE`，
   note 完整记录发布者、引用 URL、素材范围、商业使用/改编、署名及其他限制。
   核验事实不是签发许可；官方身份或开启 Handsfree 不等于授权，不编造许可或等人工补批。
   无依据则报告缺口/实际可执行的合法替代路线，不能兑现的候选不为凑数回传。
4. `heat_score` 只按可观察的新鲜度、显著性和互动信号估算，不捏造指标。
5. 不下载媒体、不发布、不提交凭据，数量不得超过 `max_candidates`。

## 检索预算与收敛（必须遵守）

6. 开始搜索前先列主题提纲（厂商/项目清单），再按提纲逐主题搜透；同一主题的
   搜索不超过 2 次，全任务搜索总数不超过 2 × max_candidates（无输入信号时按
   30 兑底）。
7. 优先抓取官方 newsroom/blog 索引页，一页覆盖该来源全部线索后再逐条打开候选页；
   页面抓取总数不超过 max_candidates + 5。
8. 二手页（聚合站、博客、内容农场）只用于获取线索，不得逐个打开阅读；拿到项目名
   后直接定位官方页。
9. 收敛条件：连续 3 次搜索无新增合格候选即停止搜索，进入查重与提交阶段；
   宁可少于 `max_candidates`，不追尾部凑数。
10. 所有拟回传候选的 `check-similar` 合并为一批并行执行，不得逐条串行。
11. 每次搜索只取前 5 条结果纳入判断；候选信息在浏览时即记为紧凑清单，
    收尾不再重述。
